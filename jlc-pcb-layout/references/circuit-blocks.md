# 功能块参考电路库（Circuit Blocks）

`assets/circuit-blocks.json` 的**人类可读版**。机器读 JSON 生成网表，人读这一份判断"这块电路对不对、参数怎么定、常见错在哪"。

15 个块覆盖工业/消费类控制板 80% 的骨架。每块给：组成、每个器件为什么在、参数怎么算、常见错误及对应 ERC 规则号。

> **料号不在这里。** 这里只给"必接什么、接在哪、参数范围"。具体型号必须由人选型后在 netlist 里填 `lcsc`——脚本编料号会造成批量买错料，这是这类工具最危险的失败模式。

---

## power_protect — 输入保护

**组成**：`J1 输入座 → F1 保险 → D1 TVS → C1 10µF → VIN`

TVS 放在保险**之后**：先让保险限流，再让 TVS 钳位，浪涌才不会先打坏 TVS。TVS 阴极接 VIN、阳极接 GND（单向）。

**参数**：`VRWM ≥ 1.1×Vop`，由 `vop` 自动推档（24V → SMBJ30A/33A 档）。保险取整板最大电流 1.5~2 倍。

**常见错误**：
- 用 `SMBJ24A` 保护 24V 母线 → 正常工作时就在击穿边缘漏电（`SCH-TVX-VRWM`）
- 钳位电压 48V 却接到耐压 36V 的 buck 上 → 浪涌时后级先死（ERC 查不了，必须查手册）
- 保险放在 TVS 之后 → 浪涌先经过 TVS，保险根本没机会动作

## power_ldo — LDO 线性稳压

**组成**：`U1 + Cin 1µF + Cout 10µF`

Cout 取 10µF 有两个作用：满足 LDO 稳定性要求（多数 LDO 要求 ≥1µF），同时充当该路的 bulk。部分 LDO 对输出电容的 ESR 有范围要求，用陶瓷电容时要查手册。

**参数**：先跑 `schem.py calc ldo --vin --vout --iout`，看 `verdict`：
- `OK` → 可以用
- `MARGINAL`（Pd >0.5W）→ 加铜箔散热或降电流
- `TOO_HOT` → **必须改 buck**

**常见错误**：
- 24V 直接 LDO 到 3.3V，功耗 6W+（99% 的项目在这里翻车）
- 输出电容只放 100nF，LDO 振荡
- 忘了 `EN` 脚的处理（悬空时行为不确定，需要上拉或接 MCU）

## power_buck — 开关稳压

**组成**：`U1 + L1 + Cin 10µF + Cout 22µF + FB 分压 R1/R2`

**参数**（`schem.py calc buck`）：
- `L = (Vin−Vout)·Vout/(Vin·fsw·ΔI)`，`ΔI = 0.3×Iout`
- 电感饱和电流 ≥ `Iout + ΔI/2`
- `Cout = ΔI/(8·fsw·ΔV)`，ΔV 取 1% Vout

24V→5V @1A / 500kHz → L≈26µH、Isat≥1.15A、Cout≥1.5µF（实际取 22µF 陶瓷，考虑直流偏压降容）。

**常见错误**：
- 电感只看感量不看饱和电流 → 大电流时感量塌陷，输出跌落
- FB 分压直接抄参考设计 → 芯片基准电压不同（0.6V / 0.8V / 1.2V），输出全错
- 输入电容离 VIN 脚太远 → 开关尖峰打死芯片（这是 PCB 阶段的问题，但原理图要标出"就近"）

## mcu_min — MCU 最小系统

**组成（四件套，缺一不可）**：

| 件 | 器件 | 省了的后果 |
|---|---|---|
| 复位 | `R 10k` 上拉 + `C 100nF` 对地 | 上电不复位或随机复位 |
| 时钟 | `Y1` + `C1/C2` 负载电容 | 不起振，或频偏导致串口乱码 |
| 去耦 | 每个 VDD 脚 100nF | 高频误动作、ADC 精度差 |
| 下载口 | SWD 4P（3V3/SWDIO/SWCLK/GND） | 没法烧程序，也没法调试 |

**注意**：本块的引脚映射用**功能名**（`VDD`/`NRST`/`XTAL_IN`…），因为不同型号引脚号完全不同。落笔前必须：
1. 选定具体型号并填入 `lcsc`
2. 从 EDA 回读引脚，跑 `schem.py bind` 把功能名映射到真实引脚号

**常见错误**：
- `BOOT0` 悬空 → 芯片有时进不了正常启动，故障极难查
- 复位按钮串在 RC 里而不是与 C 并联
- 只给主 VDD 加去耦，VBAT/VDDA 忘了
- 用内部 RC 振荡器却没删掉晶振脚 → ERC 一直报 `SCH-MCU-CLOCK`（这是故意的，让你明确选一次）

## usb_typec_ufp — USB Type-C 受电口

**组成**：`J1 16P + R1/R2 5.1k(CC1/CC2) + D1 ESD + C1 1µF`

**为什么两个 5.1k 缺一不可**：Type-C 线是正反插的，source 通过检测 CC1/CC2 上的下拉来判断"有设备"。只接一颗 → 一半的插线方向不供电 → 用户以为板子坏了。

**常见错误**：
- 只接 CC1（`SCH-USB-CC`，FAIL）
- CC 上放了 Rp（10k 上拉）→ 设备变成 DRP，行为不可预期
- ESD 放在芯片侧而不是连接器侧 → 浪涌先穿过整板
- 想做数据通信却只接了 VBUS/GND/CC

## rs485 — RS485 收发

**组成**：`U1 收发器 + R1/R2 偏置 680 + R3 终端 120 + D1/D2 TVS + R4 DE 下拉 + C 100nF + J1 端子`

**终端只在总线两端**：本块默认 `term: true`。如果这个节点是中间节点，把 `term` 设成 `false`，模块会跳过 120Ω（`optional` 件）。

**偏置**：A 上拉、B 下拉，保证空闲 `Vab≥200mV`。整条总线只在一处偏置。
- `Rb ≤ Rt×(Vcc/0.2−1)/2`，5V/120Ω → ≤1440Ω，实用 560~1k

**常见错误**：
- 每个节点都放 120Ω → 三个节点并联成 40Ω，驱动能力不够，通信距离腰斩
- 偏置方向接反（A 下拉、B 上拉）→ 空闲态被读成 1，帧错误
- `DE/RE` 直接接 MCU 不加上下拉 → 上电瞬间总线乱发
- 忘了 TVS → 现场一打雷就换芯片

## can — CAN 收发

**组成**：`U1 收发器 + R1/R2 60+60 分裂终端 + C1 4.7nF + C 100nF + J1`

**为什么用分裂终端**：两个 60Ω 串联、中点经 4.7nF 落地，给共模噪声一条低阻泄放路径。EMC 表现明显好于单个 120Ω，代价是多两颗元件。

**常见错误**：
- 终端数量不是 2（0 个或每节点都加）
- 收发器 5V 供电但 MCU 是 3.3V，TXD 高电平不够（查收发器 VIH）
- `S`（待机）脚悬空 → 芯片进待机，总线上听不到东西

## relay_drive — 继电器驱动

**组成**：`K1 继电器 + Q1 三极管 + R1 基极限流 + R2 基极下拉 + D1 续流 + J2 触点端子`

**续流二极管是硬要求**：线圈电感在关断瞬间产生 `V=L·di/dt`，几百伏的尖峰直接打穿三极管。二极管阴极接电源侧、阳极接集电极（反并联在线圈两端）。

**参数**（`schem.py calc relay`）：
- `Ic ≥ 3×Icoil`，`Ib = Ic/(β_min)×3`，`Rb=(Vdrive−Vbe)/Ib`
- β 用**最小值**的 1/3（保证饱和深度），datasheet 的 hFE 是典型值不能直接用

**常见错误**：
- 没有续流二极管（`SCH-RELAY-FLYBACK`，FAIL）
- 忘了基极下拉 → 上电瞬间继电器啪一声吸合
- 触点直接驱动感性负载不加 RC 吸收 → 触点拉弧、寿命骤降
- 用 MOS 管驱动却只看 `Vgs(th)` 不看 `Rds(on)@Vgs`

## mosfet_load — MOSFET 低边开关

**组成**：`Q1 NMOS + R1 栅极串阻 100Ω + R2 栅极下拉 10k + J1 负载端子`

负载接在电源正与漏极之间。栅极串阻抑制栅极振荡，下拉保证上电确定关断。

**常见错误**：
- 3.3V 驱动却选了 `Vgs(th)=2~4V` 的标准管 → 没完全开通，发热烧毁
- 感性负载不加续流
- PWM 调速时没核算开关损耗

---

## key — 按键输入

**组成**：`SW1 + R1 上拉 10k + C1 100nF`

按键接地，靠上拉给确定电平。并联电容做硬件消抖（τ=1ms 对应 ~10ms 消抖窗口），软件仍需去抖。

**常见错误**：
- 依赖 MCU 内部上拉（内部上拉通常 30~50k，长线时抗干扰差）
- 电容放到 1µF，按下响应变慢
- 按键与复位键共用一个网络

## led_ind — LED 指示

**组成**：`D1 LED + R1 限流`

`R=(Vcc−Vf)/I`。3.3V / 红 Vf=1.9V / 5mA → 280Ω → 取 270Ω。

**常见错误**：
- **LED 直接接 IO 不串电阻**（`SCH-LED-RES`，FAIL）—— IO 灌电流能力被 LED 的指数特性"决定"，实际上就是烧
- 多颗 LED 并联共用一个电阻 → 亮度不均，Vf 最低的那颗先烧
- 用 IO 拉电流（source）而不是灌电流（sink）→ 多数 MCU 的 source 能力弱于 sink

## i2c_port — I2C 接口座

**组成**：`J1 4P + R1/R2 上拉`

上拉值**算**出来，别抄：`schem.py calc i2c --vcc 3.3 --mode fast --cb-pf 200` → 967Ω~1771Ω，取 1k。

**常见错误**：
- 400kHz 长总线用 4.7k → 上升沿不够陡，通信不稳（最常见的 I2C 调不通原因）
- 多个 I2C 从板各自带上拉 → 并联后阻值过低，灌电流超限
- 接插件没留 GND 针

---

## uart_port — UART 排针

**组成**：`J1 4P（3V3/TX/RX/GND）`

**常见错误**：TX/RX 没交叉；调试口只留两根信号线不留 GND（示波器没法测）。

## adc_divider — ADC 分压采样

**组成**：`R1 上臂 + R2 下臂 + C1 100nF`

`Rtop = Rbottom×(Vin−Vout)/Vout`，分压点并 100nF 做电荷缓冲。

**判据**：源阻抗 `Rth = Rtop∥Rbottom ≤ 10kΩ`（12 位 SAR ADC）。24V→4.5V 用 43k/10k → Rth=8.1k，勉强合格；要更稳就把阻值整体降低（代价是静态电流）。

**常见错误**：
- 为了省电把分压做到 1MΩ → 源阻抗超标 + 噪声盖掉信号
- 直接用 5% 电阻做测量
- 忘了 100nF（采样瞬间电荷被抽走，读数偏低）

---

## buzzer — 蜂鸣器驱动

**组成**：`BZ1 + Q1 三极管 + R1 基极电阻 + D1 续流`

**有源/无源必须先问清楚**：有源给直流就响，无源必须给 PWM（频率决定音调）。选错的话板子做出来"不响"，而电路本身没错。

**常见错误**：无源蜂鸣器给直流；感性蜂鸣器不加续流；直接 IO 驱动（电流不够，且容易烧 IO）。

## 怎么加新块

1. 在 `assets/circuit-blocks.json` 的 `blocks` 里加一项，字段照现有块写全（`tag`/`keywords`/`params`/`parts`/`requires`/`erc`）。
2. 局部网络用 `#` 开头（实例化时自动加前缀，多实例不会串）。
3. 参数占位用 `${name}`，并在 `params` 里给 `default`。
4. 本文件补一节，写清"每个器件为什么在"和"常见错误"。
5. 跑 `schem.py netlist` + `schem.py erc` 验证新块自己能过 ERC（过不了的说明电路本身缺东西）。
